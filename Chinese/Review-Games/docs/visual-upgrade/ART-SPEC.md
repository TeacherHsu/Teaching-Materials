# 美術規格：Premium Miniature Toy Game World

> 正本。Claude（設計總監）撰寫，Codex 照做。數值是起點，可以為了畫面更好微調，但要在 IMPL-LOG 寫明改了什麼、為什麼改。
> 優先順序：教材正確 > 遊戲功能 > 易讀 > 效能 > 3D 質感 > 裝飾動畫。

## 0. 一句話

**一套放在暖色木桌上、做工精緻的實體桌遊**：木頭有紋理，塑膠是霧面的，紙張有厚度。光從左上方的窗戶照進來，每個物件底下都有柔和的接觸陰影。看起來像可以伸手拿起來的玩具，不要像幾何圖形堆出來的示意圖。

## 2. 3D 共用元件庫 `rg3d-kit.js`（`window.RG3DKit`）

### 2.1 渲染
- 使用 `WebGLRenderer({antialias:true, alpha:true})`；`outputEncoding = sRGBEncoding`；`toneMapping = ACESFilmicToneMapping`，`exposure 1.05`；`physicallyCorrectLights = false`。
- pixelRatio 上限：high 2、standard 1.5、light 1。
- 環境光照：`RoomEnvironment` 經 `PMREMGenerator`，`scene.environment`，強度由材質的 `envMapIntensity` 控制。
- 畫布背景要透明，桌面延伸到畫布邊緣後漸層淡出到 `--surface-0`。**畫面上不能出現跟頁面底色不同的空白色帶**（現行版本左右兩側的深木色帶就是反例）。

### 2.2 燈光預設 `LIGHT`
| 燈 | 設定 |
|---|---|
| Hemisphere | sky `#fff4e2`、ground `#b98d62`、0.55 |
| Key（暖色窗光） | Directional `#fff1dc` 1.55，位置 (-6, 12, 7)，投射陰影；high 用 2048、standard 用 1024 的 PCFSoft，`shadow.radius 4`，`bias -0.0004`，`normalBias 0.02` |
| Fill（冷色補光） | Directional `#dfe8ff` 0.35，位置 (7, 6, -4)，不投射陰影 |
| Rim | 可省略；若要加，強度 ≤ 0.25 |

### 2.3 材質庫 `MAT`（全部是 `MeshStandardMaterial`，同一種材質只建一次並共用）
| 名稱 | 顏色 | roughness | metalness | 其他 |
|---|---|---|---|---|
| `wood` | `#c58b54` | 0.62 | 0 | 程序產生的木紋 canvas 貼圖（512），紋路方向一致，對比要低 |
| `woodDark` | `#8a5a33` | 0.58 | 0 | 同一張木紋，色調較深 |
| `plastic(color)` | 參數 | 0.42 | 0 | envMapIntensity 0.45，以顏色做 cache |
| `paper` | `#fbf3e4` | 0.9 | 0 | — |
| `felt` | `#7aa38f` | 1 | 0 | 細微雜訊貼圖 |
| `gold` | `#d9a441` | 0.32 | 0.7 | 只用在寶箱、獎章、旗桿頂端 |
| `ink` | `#2b1d12` | 0.5 | 0 | 眼睛、骰點 |

### 2.4 幾何工具
- `roundedBox(w,h,d,r,seg=3)`：用 vendor 的 `RoundedBoxGeometry`；**不要再用直角 BoxGeometry 做看得到的玩具零件**。
- `blobShadow(size, opacity)`：放射漸層的 canvas 貼圖平面，貼在物件底下 +0.002 的高度，作為所有可移動物件的接觸陰影。light 檔次只用這個，不開陰影貼圖。
- 同類格子、裝飾用 `InstancedMesh` 或合併幾何，壓低 draw call。

### 2.5 角色棋子 `piece(team)`：四隊四個角色
共通：高約 0.95，底座是隊伍色的圓盤（直徑 0.78、厚 0.12、圓角），**底座頂面印白底數字 1–4**（canvas 貼圖、粗體）。三重辨識是「角色外形、顏色、數字」，任何一項單獨失效時，靠另外兩項仍能分辨。正面有兩顆黑色圓眼加粉色腮紅，讓角色看得出臉朝哪裡；移動時面向前進方向。

| 隊 | 角色 | 外形重點（只用基本幾何：capsule＝cylinder＋sphere） |
|---|---|---|
| 1 紅 | 小探險家 | 圓胖身體，頭戴寬帽簷探險帽（米色），背一個小背包 |
| 2 藍 | 迷你機器人 | 圓角方塊身體，圓角方塊頭，深色護目鏡加兩顆亮眼，頭上一根天線，天線頂端是小球 |
| 3 綠 | 小恐龍 | 水滴形身體，背上一排 3–4 片圓錐背刺，短尾巴 |
| 4 紫 | 書本精靈 | 圓身體，背後一本打開的小書當翅膀，頭頂一顆金色小星星 |

剪影要求：四個角色縮到 40px 高、轉成灰階後，仍然一眼分得出誰是誰。

動作：
- `idle`：只有「目前輪到的隊伍」播放，呼吸式上下浮動 2%，週期 2.4s。
- `hop(from,to)`：每走一格跳一次，弧高 0.35、220ms，落地壓扁 6% 後回彈。
- `cheer()`：跳起並轉一圈，600ms。

低動態模式：idle 與 cheer 都不播，hop 改成直接到位（每格 80ms 的位移，沒有弧線）。

### 2.6 骰子 `dice()`
- 象牙白霧面塑膠，圓角立方體（邊長 0.9，圓角 0.14），骰點是凹下的深色圓點，1 點用紅色。
- `roll(n)`：**n 由遊戲邏輯傳入**。動畫流程：拋起（弧線）→ 落地彈兩次 → 滾動停在 n 朝上，共 1100–1300ms。落地時接觸陰影跟著縮放。
- 停下後保持 n 朝上，從預設鏡頭看得清楚。
- 低動態模式：直接顯示 n 朝上，並加 150ms 淡入。

### 2.7 生命週期（從 `scene3d.js` 移植語意，不得退化）
- 非同步載入，不阻擋 2D 操作。
- 以下情況降回 2D：系統減少動態（經 `RG.systemReduced()`）、`body.calm`、寬度 ≤760px、載入失敗或逾時、WebGL 初始化失敗、context lost、連續幀時間過慢。
- 閒置不持續渲染（有補間時才跑 rAF）；頁面隱藏、降級、dispose 時要讓所有等待中的 Promise resolve，**回合不能卡住**。
- 「畫面設定」列（減少動態、投影模式、顯示 3D 覆蓋）的行為與現行版本一致。

## 3. 大富翁黃金樣板 `scene3d-monopoly.js`

### 3.1 鏡頭
- 透視鏡頭，fov 30–34，仰角約 52–56°，水平不旋轉（棋盤邊與畫面平行，格子上的字才不會斜）。
- 自動取景：棋盤外框左右各留 4–6% 邊界，寬螢幕與 4:3 都要填滿。
- `focusPlayer` 只做輕微推近（≤8%），並在 500ms 內回到預設；不可大幅旋轉。

### 3.2 棋盤
- **木製托盤**：外框 `wood`，厚 0.55，框寬 0.5，圓角 0.12；內底 `paper` 色。整體放在 `woodDark` 桌面上，桌面用寬約 2 倍棋盤的圓角平面，邊緣漸層淡出。
- **格子**：每格是 `roundedBox(1.62, 0.2, 1.62, 0.07)` 的 `paper` 色塊，相鄰格子之間有 0.06 的縫，看得出一格一格。課次格朝棋盤內側的那一邊有一條 0.3 寬、凸起 0.04 的**課次色帶**（`--c1..c6`）。
- **特殊格**（只放立體道具，不放大型文字）：
  - 起點：綠色三角旗，加一塊小小的起跑木牌。
  - 機會：金色「?」積木方塊。
  - 命運：一疊三張微微錯開的卡牌。
  - 休息站：小長椅加一個茶杯。
  - 綜合複習：一疊三本藍色系的書。
- **DOM 標籤**：維持 DOM（易讀、可縮放），放在格子的**內側半邊**，是米白圓角小牌加課次色點，字 ≥ 16px（1366 寬時）。建築放在格子的**外側半邊**，所以標籤永遠不會被建築擋住。

### 3.3 地產建築（六課六種，以參數化工廠產生）
| 課 | 建築 | 外形 |
|---|---|---|
| 1 | 書本屋 | 一本直立的厚書當牆面，上面加三角屋頂，正面開一扇圓拱門 |
| 2 | 文具店 | 方形小店，前面有條紋遮陽棚，屋頂立一支鉛筆 |
| 3 | 小學堂 | 長方形校舍，加一座小鐘樓 |
| 4 | 圖書館 | 正面四根柱子，上面是三角山牆，底下兩階台階 |
| 5 | 故事小屋 | 圓柱形小屋，圓錐屋頂，加煙囪 |
| 6 | 閱讀塔 | 細長塔身，頂端是一疊三本書 |

- 佔地 ≤ 0.9×0.7，高 ≤ 0.85；牆面用 `paper`；**屋頂與門用隊伍色**，屋頂插一面寫隊伍數字的小旗。
- 還沒賣出的地：只放一塊淺色地基線框加一支小木牌（不放建築）。
- `setOwner(cell, team)` 的動畫：格子色帶先亮 300ms，接著建築從地基「長」出來（scale.y 從 0 到 1.08 再回到 1，`--ease-pop`，700ms），旗子落定，屋主角色 `cheer()`。
- 低動態模式：建築直接出現。
- 同一課的兩塊地都買下時，兩棟建築之間加一面連接的隊伍色小旗串，表示通行費加倍。

### 3.4 中央場景（高度 ≤ 0.7，不可遮擋任何格子）
- 中央是 `felt` 綠色桌墊加 `woodDark` 細邊。
- **骰子盤**：圓形淺木盤，放在中央偏前，骰子在盤內落地。
- 四角低矮擺設：迷你圖書館（中央最主要的景物，偏後放）、兩支鉛筆路燈（燈罩發暖光，用 emissive 0.4，不要用點光源）、一個小寶箱、一面「課文探險」小旗。
- 原本鋪在中央的「課文探險」大字拿掉，改成旗面或木牌上的短字。

### 3.5 棋子
- 用 2.5 的角色。同格多人時採 2×2 錯位（±0.36），永遠不完全重疊。
- `moveToken` 逐格跳躍；`stepMark` 在格子上顯示足跡步數（沿用現有 DOM 的 `rg3d-cell-step`，或改用 3D 小牌，但數字一定要清楚）。

### 3.6 效能預算
- 三角形 ≤ 80k；draw calls ≤ 160；canvas 貼圖 ≤ 10 張，每張 ≤ 1024。
- standard 檔次在無頭 swiftshader 上單幀 ≤ 50ms（只作相對參考，不等於實機）。

### 3.7 側邊面板（黃金樣板也要一起做到）
- 目前隊伍的卡片：左側 6px 隊伍色邊框、`--shadow-toy`，並顯示角色小圖示。小圖示可以用 3D 角色離線渲染成 data URL，也可以用 inline SVG，外形要跟 3D 角色一致。
- 同一時間只有一個主要按鈕（`--action`）；其他按鈕降為次要樣式。

## 4. 密室黃金樣板（`detective3d.js`＋`detective.css`＋`detective.js` 任務手冊）

老師的要求（原話）：「必須讓學生產生探索房間的感覺，而不是把原本的家具與線索數字換成更精細的模型。」
同時要守住特教底線：**每個學生都一定找得到下一步**。

### 4.1 房間：從「家具擺設圖」改成「有故事的剖面微縮屋」
- **剖面娃娃屋**：後牆和左牆要有厚度（0.25），切面露出米白色斷面，地板邊緣做成木頭的切面。整間房間放在一塊 `woodDark` 底座上，像一件擺在桌上的模型。
- **牆面**：分成上下兩段，下段是護牆板加踢腳板，上段是壁紙。壁紙用 canvas 程序產生細小圖案，依六種主題換圖案和顏色。
- **地板**：一條一條木地板（程序木紋），地毯有花紋與流蘇。
- **光線說故事**：
  - 後牆開一扇窗，key light 從窗外斜射進來。
  - 在窗框投影的位置，貼一塊 additive、低不透明度（≤0.12）的「光束」平面，假造一道光柱。
  - 檯燈或油燈用 emissive 發暖光。只在 high 品質時加一盞 PointLight，強度 ≤ 0.6、距離 4。
  - 整體比棋盤類遊戲暗一點、暖一點（exposure 0.92），讓人有「夜裡調查」的氣氛。但不可以暗到看不清標記。
- **前景層次**：靠近鏡頭的右下角放 1–2 個前景物件（大盆栽、半開的門框或木箱），只露出一部分，**而且不可以擋住任何標記的投影位置**。
- **主題道具**：各主題放 3–5 件專屬小物，例如：
  - 實驗室：燒杯架
  - 森林：松果籃、掛著的油燈
  - 博物館：展示罩加小雕像
  - 教室：黑板、課桌

  機關物件（保險箱、鎖櫃、打字機、放大鏡、推理機、布告欄、出口大門）每一件都要做出可以辨識的造型，且都使用 kit 的 `roundedBox` 與材質庫。
- 所有物件都要有接觸陰影（blob），並使用 kit 的燈光與材質，跟大富翁同一套語言。

### 4.2 探索感（鏡頭）
- 拖曳水平旋轉放寬到 ±0.9 rad，垂直加 ±0.12 rad 的小幅俯仰。
- 縮放：滾輪或兩指捏合，距離在預設值的 0.72–1.2 倍之間。
- **鏡頭邊界**：鏡頭不可以穿進牆內；任何角度下，房間的地板中心都要留在畫面裡。
- 新增按鈕「⟲ 回到預設視角」，放在畫面左下角，至少 48px。
- **聚焦**：點機關清單的項目或 3D 物件時，鏡頭在 500ms 內轉到看得到該物件的角度並略微推近，同時物件發一次光暈脈衝。低動態模式下直接切換過去。
- 「固定視角」開關：鎖住拖曳與縮放，給操作能力較弱的學生使用。設定存在 localStorage（`dt-fixed-view`）。
- 平面圖模式保留，玩法完全相同。

### 4.3 標記：兩種模式（設定存在 localStorage 的 `dt-marker-mode`，預設 `standard`）
- **standard（探索）**
  - 還沒調查過的搜查點（holder）只顯示一顆 18px 的發光小圓點，觸控熱區 ≥ 44px，用透明 padding 撐出來。滑鼠移入或鍵盤聚焦時，才展開圖示與名稱。
  - 小圓點的 3D 位置如果被其他物件擋住（從鏡頭打 raycast 判斷），就淡出到 20%，提示學生「轉一轉才看得清楚」。
  - **「下一步目標」（`dt-target`）永遠完整顯示圖示加名稱，而且絕不淡出。**
  - 鎖住的機關只顯示鎖頭小圖示，不顯示編號。
- **high（高辨識）**：維持現行行為，所有標記都顯示編號、圖示與名稱，也不做遮擋淡出。
- 兩種模式的切換放在密室上方工具列（`dt-bar`），文字寫「標記：探索／全部顯示」。
- 平面圖模式一律使用 high。

### 4.4 物件互動動畫（在 `animate(kind,id)` 擴充，與 core 狀態同步，低動態時直接到終態）
| 物件 | 動畫 |
|---|---|
| 書架上的書 | 一本書抽出 0.2，再翻開 |
| 抽屜 | 拉出 0.35 |
| 相框 | 往側邊翻開 |
| 盆栽 | 葉子晃一下 |
| 保險箱 | 轉盤轉動，接著門轉開 100° |
| 鎖櫃 | 鎖頭的鎖勾彈起，再掉落 |
| 打字機 | 按鍵依序下壓 |
| 放大鏡 | 抬起並閃過一道高光 |
| 出口大門 | 門轉開，門縫透出光（沿用現有效果並加強） |

找到線索時，現有的紙卡飛出（`paper`）保留，並在筆記本的線索卡上蓋一個「已蒐證」印章（CSS 動畫 400ms）。

### 4.5 偵探任務手冊（取代右側「機關清單」）
由上到下：
1. **目前任務卡**：大字寫出一件下一步要做的事，旁邊一顆「前往」按鈕，按下去觸發聚焦。這張卡永遠在最上面，而且不可以收合。
2. **線索 n/5**：用一排卡片圖示表示，已找到的卡片是實心的，點下去開啟筆記本。
3. **可以調查**：列出目前可以操作的項目。
4. **尚未解鎖**：可以收合，預設收合，標題顯示數量。
5. **已完成**：可以收合，預設收合。

DOM 規則：

## 5. 蛇梯棋（`scene3d-snakes.js`，從 scene3d.js 搬到 kit）

- **托盤、格子、燈光、鏡頭**：沿用大富翁的同一套。格子以 `paper`／淺蜂蜜色 `#f1d49e` 交錯排列，相鄰格之間留 0.06 的縫。
- **終點格**：放一座金色獎盃（`gold`）。
- **起點格**：放一面綠旗。
- **圖層優先順序**（由高到低，後面的不可以遮住前面的）：
  1. 格號（DOM，字 ≥ 18px）
  2. 棋子
  3. 事件標記
  4. 蛇和梯子
  5. 裝飾
- **格號與方向箭頭**：格號放在格子左上角。方向箭頭縮小成 12px 灰色，放在右下角，不可以和格號搶注意力。
- **事件標記**（例如「多走 1 格」）：
  - 改成格子上的 3D 金色小星星。
  - 文字只用 DOM 小標，放在格子底邊，**不可以疊在格號上**。
  - 同一格同時有足跡步數時，步數優先顯示，事件小標往下讓位。
- **玩具蛇**：
  - 蛇身是 CatmullRom 曲線的 TubeGeometry，粗細從 0.22 漸細到 0.08，懸在格面上方 0.18。
  - 塑膠表面有兩色環紋（canvas 貼圖），每條蛇一組配色：綠＋黃、橘＋米、藍＋淺藍。
  - 蛇頭是扁圓的頭，有兩顆白底黑瞳的眼睛和一條小紅舌。**蛇頭一定在高號格（滑下來的起點）**，尾巴在低號格，方向不可以有歧義。
  - 曲線避開格號區（格子左上 40%）；如果避不開，就把那一段升高到 0.35。
- **梯子**：
  - 兩根 `wood` 圓柱扶手，加等距橫桿。
  - 兩端各有小底座並帶接觸陰影；梯子斜放，低端貼著棋盤，高端抬高 0.15。
- **爬梯**：棋子沿著梯子一階一階往上跳，每階 120ms。
- **滑蛇**：
  - 棋子沿蛇身曲線滑下，約 900ms。滑之前蛇眨一次眼，蛇頭輕輕點一下。
  - 不可以出現張嘴、追逐、震動畫面這類嚇人的效果。
- **低動態模式**：棋子直接到達終點格；蛇不動，梯子不動。
