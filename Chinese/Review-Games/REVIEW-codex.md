# 國語複習遊戲視覺與互動審查

審查日期：2026-10-16。範圍：指定五個 HTML、common.css、common.js；G3A.js 僅確認資料結構。
本次為原始碼靜態審查，未啟動瀏覽器、未實測投影／iPad 語音；尺寸、流程與風險依程式判讀，不把推估當成實機結果。僅新增本報告，未修改遊戲、題庫或交接檔，未執行 git 指令。
行號均指本次讀取的原始檔；下列數值是實作起點，仍需教室最後一排與 iPad 橫直向驗收。工時為一位熟悉程式的開發者估算，含基本驗證，不含整批題目人工編審。

## 總評

- 暖色底、大按鈕、離線題庫、可重播朗讀與支持層，是適合資源班的起點。
- 現在較像「乾淨的教學工具」；缺少棋子角色、清楚路徑與完成小任務的成就感，但不需要大量裝飾。
- 首要問題是錯後缺少教學鷹架、賓果回饋停留不足，以及遊戲實際難度與共用支持說明不一致。
- 大富翁／蛇梯棋仍可能靠骰運勝出；哆寶找相同字不等於理解詞義，應另外確認學習成果。
- 先處理 P0，再用一致的本機圖示、角色棋子與短回饋提升吸引力；三、四、六年級共用清爽風格，支持依需求選，不依年級貼標籤。

## 各款專屬建議

以下為上述優先項目的遊戲落點，不另重複計工時。

### 遊戲選單 index.html

1. **P1｜把選擇依據變成看得懂的動作。** `index.html:16–19,29–30`：卡片固定呈現「小棋盤圖→名稱→一句玩法→人數」，不讓學生先讀租金、蛇頭等完整規則。建議卡片內文至少 20–22px，投影 24px。
2. **P1｜先選情境再推薦。** `index.html:23–30`：提供大按鈕「自己練」「全班玩」；自己練優先呈現賓果／哆寶／單人蛇梯，大富翁清楚標「2–4隊」。不應把單人學生帶到只能多隊的起始設定。
3. **P1｜提供不計分示範。** `index.html:29–30`：每張卡加獨立「看怎麼玩」按鈕，示範一次點選與一次修正；按鈕與整張卡連結應為同層，避免在 `<a>` 裡再包互動按鈕。
4. **P2｜降低教師資訊搶注意。** `index.html:26–28`：主標縮為「三上・國語複習」，出版社／題庫數量／第1–6課放可展開資訊；提供有文字的年級切換，保留網址 `?g=`，不用靠修改網址。

### 課文大富翁 monopoly.html

1. **P0｜地產課次與實際題目要相符。** `monopoly.html:32,63,114`、`common.js:101–105`：目前找不到該課牌就抽別課；只選部分課次時仍有全部六課地產。將棋盤以所選課重排，或把無題地改為「綜合複習」；題堆對該課用盡時補該課，不默默跨課。驗收只選第2課，不能顯示第5課地卻出第2課題。
2. **P0｜補獨立的當前位置卡。** `monopoly.html:11–21,75`：格內保留「第2課」等短標籤；中央顯「你在：第2課／這次任務：找詞義」，完成後才呈現買地結果。不要把字縮至窄版約 10.2px，也不要讓棋子壓住地名。
3. **P0｜經濟挫折不能阻斷學習。** `monopoly.html:116–126,145–152`：沒錢仍做題；支持模式提示後完成可免費通過。結算並列「財富」與「今天學會的線索」，不把最高資產等同最高語文能力。
4. **P1｜把繁複算帳留給系統。** `monopoly.html:45,117,125,149`：教師規則可展開，學生每回合只顯一條任務；帳務以「+50 複習獎勵」靜態小標記 800ms，再由「換下一隊」前進。命運改「發現閱讀角，休息一下」等中性事件，避免遺忘物品被道德化扣錢。
5. **P1｜強化路徑與所有權。** `monopoly.html:12,17–18,87–91`：格緣加稀疏方向箭頭；所有權使用隊徽＋編號，別只靠六種課色與四種隊色。配色區別「課次」和「隊伍」時以色帶／徽章不同形狀承載。

### 語文蛇梯棋 snakes.html

1. **P0｜每回合都有題、終點不跳過學習。** `snakes.html:97–107`：普通格與終點目前不出題；改先完成一題再移動，特殊格只決定額外效果、不重複增加題量。增加「全隊合計完成8題」合作目標，抵達終點另列為棋盤結果。
2. **P0｜讓失敗可修復。** `snakes.html:33,101`：29→18 等長距離倒退容易放大挫折；支持模式先給線索與重試，學過後留原格；一般模式可選最多退3格。不要在公布答案後立刻連續倒走，先讓學生看完教學回饋。
3. **P1｜蛇像蛇、梯像梯，但不遮數字。** `snakes.html:63–74`：現為曲線與虛線組合；梯子改兩條平行軌＋橫檔，蛇加小頭部／方向箭頭，端點標「3→11」。路徑降至背景層、數字另置有底色小標籤，棋子仍在最上層。
4. **P1｜明示蛇行順序。** `snakes.html:35,54–56`：每列起點放低干擾方向箭頭，當前格深框，側欄以 28–32px 顯示「現在8格→要到12格」。移動後等「換下一隊」再換焦點，避免旁白還沒播完隊伍已變。
5. **P2｜單人採短旅程。** `snakes.html:39,106–108`：個人模式可選5題任務；結尾以本次學過的兩個詞／一個策略為主，不只獎盃。加入「暫停」且不公開倒數，讓長棋局有退出點。

### 語詞哆寶 dobble.html

1. **P0｜支持層先練辨識，再增加視覺變化。** `dobble.html:26,61–72`：4詞固定位置、水平字、相同大小；6／8詞才逐步增加位置變化。iPad 直向以矩形雙卡固定槽取代上下兩張440px圓卡；保留雙卡完整可見與 ≥52px 點擊高度。
2. **P0｜找同詞後補一次詞義提取。** `dobble.html:88–94`：現在找到即得星再看意思，無法知道是否理解；可設「找一找→聽短解釋→兩個意思選一個」的可選學習回合。支持可先聽意思，隔幾題再提取；找同詞與懂詞義各有圖章，不以速度代替理解。
3. **P0｜給可主動使用的提示。** `dobble.html:81,88`：支持自動朗讀只念操作，不念卡片內容。增加「聽左卡／聽右卡」，朗讀時同步框出正在念的詞；一般點擊仍作答，避免單擊既朗讀又判錯。連錯兩次時提示「先比第一個字，再看後面的字」，提供縮小搜尋範圍，仍由學生完成。
4. **P1｜不要宣稱目前已在訓練形似字。** `dobble.html:51–58`、`index.html:18`：overlap 只比較相同字元，非部件形似關係；改文案為「找相同語詞、仔細看每個字」。若要正式訓練形似字，另導入教師核定的混淆組，配差異部件提示，不以演算法猜字形或字音。
5. **P1｜收尾不以快與少錯作唯一成就。** `dobble.html:53–59,84,96–101`：目標可立即重複抽到；用一小包詞輪替並安排錯詞稍後回來。結尾顯「完成5回，練過這3個詞」，用時／錯次移至教師詳情；保留詞義卡和「再練這些詞」，不要清空雙卡只剩成績。

### 語詞賓果 bingo.html

1. **P0｜讓學生有時間把詞與意思連起來。** `bingo.html:82–91`：答對停留，顯示 ✓、詞與短義，按「下一題」才前進；「聽解釋」常駐。挑戰層若要保留聽力目標，可遮文字但由教師選，不能強迫所有慢讀者靠讀長義項。
2. **P0｜支持版降低搜尋負荷，不只縮格數。** `bingo.html:13,19,27,70`：3×3 每格至少 28px、長詞保留完整字序，避免 `word-break:break-all` 任意拆詞；精簡題框為「意思：……／點出語詞」。短義由教師審核，不用機械截斷；完整解釋放「多看一點」。
3. **P0｜線索應逐級，而不是閃答案。** `bingo.html:77–79`：按當題嘗試數決定提示；先標題幹關鍵概念，再讓學生選擇兩格提示，最後才揭曉。900ms 框線改持續顯示並帶文字；已提示答案者不記為獨立答對。
4. **P1｜分隊投影與個人模式明確分流。** `bingo.html:34,56`：投影版放大題目至36px、詞至少30px，右上只留「輪到第2隊」與「下一題」；格子不需自行填寫。個人版可有「我想先聽」與跳過，不以全班搶快操作為預設。
5. **P1｜賓果後補回未練到的內容。** `bingo.html:45–46,84–88`：一條線可能很快結束、未抽詞尚未學；呈現「已連線！要收集剩下的3個詞嗎？」與「結束」，不強制加長。跳過的詞在間隔後再出，另列「還想練」，不要把連線直接稱為全部會了。

## 不建議做的事

- 不加滿版彩紙、閃爍倒數、背景音樂、持續跳動角色；回饋只出現在操作相關區，動態可關。答錯不震動、不播放嘲笑聲。
- 不加速度排行榜、全班公開錯題排行、連勝中斷懲罰、隨機寶箱或每日登入壓力；識字慢的學生也應能靠修正與理解取得成就。
- 不把所有支持綁成「簡單模式」，不以三年級固定支持、六年級固定挑戰；教師可獨立設定朗讀、選項數、計時與提示。
- 不用大量 emoji、裝飾字型、紋理、漸層與角色擠壓文字；六年級可選簡潔徽章，不必一律擬幼化。文字與目標字維持標準正體字型。
- 不把字音題的選項全自動念出、導致聽音直接洩答；先定義測驗目標。現有 `noSpeakOptions`／注音例外應保留；若新增「聽音選字」要明確當成另一題型。
- 不直接縮字解決擠版，也不把全篇課文搬入視窗；只呈現合法、經審核的必要短線索，必要時引導看課本。
- 不用合成語音當作教育部字音查證；新注音與多音字仍須依教育部辭典／教育百科查核。iPad 無可用離線語音時須能繼續看字作答，不保證合成語音一定離線。
- 不引入外部 CDN 圖庫、帳號、學生姓名／代碼／照片、雲端學習排名；圖示以 repo 內自製 SVG／CSS 為主，匿名本局練習狀態可在結束時清除。

## 建議驗收方式與依據

- 教室：以實際投影解析度從最後一排確認題幹、四個選項、目前隊伍與棋子編號；上述投影字級只是起點，若仍看不清應減資訊、再放大。
- iPad：直／橫向各走完整一局；檢查哆寶無碰撞、雙卡可同看，長題可捲但主要操作不遮住選項；放大文字後仍可操作。離線、語音不可用、減少動態各測一次。
- 流程：每款各走獨立答對、提示後答對、連錯、跳過／逾時、結束與重玩；驗證朗讀不被下一題截斷、錯題在間隔後出現、只選一課不出現誤導課次。
- 小規模觀察三、四、六年級及需要支持的學生：能否自行開始、能否說出／點選一個學到的詞義、誤觸與找不到下一步的位置。以行為觀察迭代，不先假定角色或色彩一定提升成效。
- 提取與間隔複習依據：[IES／WWC：Organizing Instruction and Study to Improve Student Learning](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)。指南支持分散學習與以測驗促進記憶；本報告的2–3題間隔屬設計起點，非固定最佳值。
- 對比依據：[W3C：Contrast (Minimum)](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html)。一般字4.5:1、大字3:1為基礎門檻，投影仍需現場驗證；本報告建議52px以上點擊區是針對兒童操作的設計目標，並非宣稱是 WCAG 的最低規定。
