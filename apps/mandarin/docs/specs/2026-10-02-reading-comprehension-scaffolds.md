# 讀懂課文：分文體的閱讀理解鷹架設計

日期：2026-10-02｜狀態：**規劃，待 CF 核可，尚未實作**

承 `2026-09-30-structure-map-redesign.md`（CF 自己的規格，分層原則沿用不變）
與 `2026-10-01-ref-site-adoption.md`。參考站 2026-10-01 23:07 的版本把
「讀懂課文」整個改寫過，本文以它為對照，但**不照抄**——它的做法有幾處
不適合我們的資料與學生。

---

## 0. 先講結論

**目前「讀懂課文」最大的問題不是缺功能，是缺「證據」。**

參考站整套鷹架的樞紐只有一個：每一題都知道**答案在課文的哪幾句**（`keys`），
所以提示可以「用螢光筆把那幾句畫出來」。我們 317 題裡**一題都沒有**這個欄位，
`scaffold` 98 筆全部是同一句佔位字串「回到課文或插圖找線索。」——等於沒有提示。

沒有證據句，再漂亮的題型都只是換包裝；有了證據句，現有的題目立刻就能做出
三層漸進提示。所以本規格的第一優先是**補證據句**，不是加題型。

## 1. 現況盤點（全部對照實際資料，不是憑印象）

| 資產 | 現況 | 評價 |
|---|---|---|
| `reading_questions.strategy_tag` | 221/317 題有，用 **PIRLS 四層次**（提取訊息 83、推論訊息 62、詮釋整合 29、比較評估 23…） | **很強的基礎**，台灣閱讀教學的共同語言，直接可用 |
| `reading_questions.options` | 只有 96/317 題有選項 | 其餘 221 題是開放提問，目前無法自動判定 |
| `reading_questions.answer_hint` | 221 筆 | 有內容，但未分層 |
| `reading_questions.scaffold` | 98 筆**全部同一句** | 形同虛設，要重做 |
| `paragraph_summary.structure_role` | 287 筆，但 160+ 筆是「第4段重點」這種無意義標籤 | 根因見 9/30 規格 §1：一段一角色的模型錯配 |
| 課文全文 | 有（加密），逐字帶注音與朗讀用字 | **可以做螢光筆標記**——這是關鍵 |
| 文體 | **沒有任何欄位** | 要新增 |

### 1.1 五冊的結構角色長得完全不一樣

```
一上  開端／發展／收束                      ← 記敘文基模，乾淨
二上  （12 課全部沒有）                      ← 空白
三上  分說／總說、困擾／嘗試、發現／分析      ← 說明文與論說文基模，乾淨
四上  「游泳】想像、歡樂與自信」              ← 內容標籤，混進了段落主題
六上  「【第一大意】女兒被冷落」              ← 內容標籤，而且前綴是編號不是角色
```

這正是 9/30 規格要解決的事：**文體基模**（可遷移、可作答）和
**內容標籤**（只屬於這一篇、只能顯示）被混在同一個欄位。四上、六上那 24 課
的值全部屬於第二層，卻被當成第一層在用。

## 2. 設計主張

### 2.1 鷹架不是「給提示」，是「把看不見的歷程變成看得見的動作」

對閱讀困難的學生，「回到課文找線索」這句話沒有作用——他不知道回到哪裡、
找什麼、找到了要怎麼用。真正的鷹架要把這個歷程拆成**他做得到的動作**：

| 熟練讀者腦中發生的事 | 拆成學生做得到的動作 |
|---|---|
| 掃視全文抓結構 | 看課文地圖，點每一格聽它在說什麼 |
| 定位答案所在段落 | 課文地圖上那一格會亮起來 |
| 在段落中找證據句 | 證據句用螢光筆畫出來 |
| 比對問題與證據 | 證據句就在題目下方，不必翻頁 |
| 排除不合理選項 | 最後一層提示才刪去明顯錯的選項 |

**提示的順序就是歷程的順序**，不是「由弱到強的暗示」。這一點和參考站一致，
我認同並沿用。

### 2.2 提示分三層，而且**每一層對應一個策略動作**

```
第 1 層：想一想     → 指向策略（「這題問的是原因，課文裡通常會寫在結果的前面」）
第 2 層：找位置     → 課文地圖那一格亮起來 ＋ 展開那一段
第 3 層：看證據     → 證據句用螢光筆畫出來
（答錯到上限才揭曉答案，由 wrongLimit 控制，支持層是 1）
```

**不做「刪去法」當提示。** 參考站有這一層，但它教的是應試技巧不是閱讀理解；
而且我們支持層只有 2 個選項，刪去法等於直接給答案。這是我和參考站的分歧，
理由寫在這裡以免日後被當成遺漏。

### 2.3 螢光筆標記的三種用途要分開

參考站用了 `keys`（答案句）與 `keys2`（上下文句）兩種。我們再分一層：

| 類型 | 畫什麼 | 什麼時候出現 |
|---|---|---|
| `evidence` | 答案的直接證據句 | 第 3 層提示，或答錯揭曉時 |
| `context` | 幫助理解但不是答案的上下文 | 第 2 層提示，和段落一起展開 |
| `signal` | 文體的訊號詞（因為、所以、first、總之） | **文體教學專用**，見 §3 |

第三種是我要加的。訊號詞是文體辨認的可遷移線索——學生學會「看到『總之』
就是結論」，換一篇文章還能用，這才是閱讀策略而不是這一課的知識。

## 3. 分文體的鷹架設計

五冊的課文可歸成四類。**文體決定三件事**：課文地圖長什麼樣、布題問什麼、
訊號詞畫哪些。

新增 `genre` 欄位（封閉集合，可驗證、可回歸測試）：

```json
"genre": "narrative" | "expository" | "argumentative" | "poetry"
```

### 3.1 記敘文 narrative（一上、二上、四上多數、六上部分）

| 項目 | 設計 |
|---|---|
| 課文地圖 | **時間軸**：開端 → 發展 → 高潮 → 結尾。橫向排列，有箭頭 |
| 核心活動 | 排順序（事件卡依時間排）——現有的 `order` 步驟就是這個，保留 |
| 布題重點 | 誰、在哪裡、做了什麼、為什麼（提取）→ 心情怎麼變（推論）→ 如果是你（反思） |
| 訊號詞 | 時間詞（後來、最後、有一天）、因果詞（因為、所以、於是） |
| 特有鷹架 | **心情線**：每一段標一個心情（開心／難過／緊張），連成一條折線。
記敘文的理解難點是「情節帶動情緒」，把它畫出來比用問的有效 |

### 3.2 說明文 expository（三上「時間是什麼」「妙用便利貼」）

| 項目 | 設計 |
|---|---|
| 課文地圖 | **總分結構圖**：總說在上、分說在下，縱向樹狀 |
| 核心活動 | **分類**（參考站的 `sort`）——把句子卡歸到正確的分項底下。
這比排順序更貼近說明文的結構：說明文的段落順序常可互換，排順序會變成瞎猜 |
| 布題重點 | 這一段在說哪一點（提取）→ 這個例子是為了說明什麼（推論）→ 幾個分項的共同點（整合） |
| 訊號詞 | 列舉詞（第一、另外、除此之外）、舉例詞（例如、像是）、總結詞（總之、由此可知） |
| 特有鷹架 | **分項計數**：地圖上先告訴學生「這一課說了三件事」，再一格一格填。
說明文的學生最常漏掉其中一項 |

### 3.3 論說文 argumentative（三上「提早五分鐘」、六上「孔子說的話」）

| 項目 | 設計 |
|---|---|
| 課文地圖 | **論證結構圖**：論點 → 論據① ② ③ → 結論 |
| 核心活動 | **配對**：把論據配到它支持的論點。或判斷「這句是論點還是論據」 |
| 布題重點 | 作者主張什麼（提取）→ 用什麼理由支持（推論）→ 你同意嗎、為什麼（評估） |
| 訊號詞 | 主張詞（我認為、應該）、理由詞（因為、理由是）、讓步詞（雖然、但是） |
| 特有鷹架 | **論點／論據分辨**：這是論說文最核心也最難的一步。
先給「這句話是在說『我覺得』還是在說『為什麼』」的二選一，再進階 |

### 3.4 詩歌 poetry（一上「大風吹」、二上「我的心情」、六上「遇見自己」）

| 項目 | 設計 |
|---|---|
| 課文地圖 | **不做結構圖**。詩的結構不是學生此刻該學的 |
| 核心活動 | **詩句解碼**（參考站的 `decode`）：「詩裡說 X，其實是什麼？」 |
| 布題重點 | 這句在寫什麼景（提取）→ 這個比喻是把什麼比成什麼（詮釋）→ 讀起來是什麼感覺（反思） |
| 訊號詞 | 不畫訊號詞，改畫**比喻的兩端**（本體與喻體用不同顏色） |
| 特有鷹架 | **比喻對照**：左邊是詩裡的說法、右邊是真實世界，中間連線。
這是詩歌理解的核心轉換 |

> **不得為了「每一課都要有地圖」而硬套。** 這條直接引用 CF 9/30 的總原則：
> 既有形式無助於理解時，換一種做法，或者不出題。詩歌就是這樣的例子。

## 4. 資料模型

### 4.1 新增與修改

```jsonc
// 課次層
"genre": "narrative",                    // 新增，封閉集合，白名單驗證

// paragraph_summary[]
"structure_type": "開端",                 // 新增：文體基模，封閉集合，可作答
"section_label": "【第一大意】女兒被冷落",   // 改名自 structure_role 的內容標籤，只顯示
"signals": ["有一天", "後來"],             // 新增：這一段的文體訊號詞

// reading_questions[]
"strategy_tag": "推論訊息",                // 已有，保留
"evidence": {                             // 新增：答案的證據
  "paragraph_no": 3,
  "sentences": ["瘧疾是經由蚊子傳染的"]     // 逐句照抄課文，匯入時驗證確實存在
},
"context": { "paragraph_no": 2, "sentences": [...] },   // 新增，選填
"hints": [                                // 取代現在那句佔位的 scaffold
  { "level": 1, "text": "這題問的是原因..." },
  { "level": 2, "type": "locate" },       // 第 2、3 層由程式產生，不必逐題寫
  { "level": 3, "type": "evidence" }
]
```

### 4.2 版權界線（沿用既有規則，不放寬）

- `section_label` 照抄官方結構表 → **只顯示、不作答**，且僅在揭曉時出現。
- `evidence.sentences` 逐句照抄課文 → 課文本來就在加密檔裡，**不另外存一份明碼**。
  改存**句子在該段的索引**，渲染時從解密後的課文取，匯入時驗證對得上。
  這一條很重要：證據句若以明碼存進 lesson JSON，等於把課文片段漏到公開 repo。
- `structure_type`、`signals`、`hints[].text` 是**我們自己寫的**，可公開。

## 5. 落地順序

| 階段 | 做什麼 | 產出 | 為什麼排這個順序 |
|---|---|---|---|
| A | 補 `genre`（55 課） | 白名單＋驗證 | 後面全部依賴它；工作量最小 |
| B | 補 `evidence`（317 題） | 匯入器＋人工覆核 | **沒有它鷹架做不出來**，是真正的瓶頸 |
| C | 三層提示引擎 | `ReadingQuestions` 改寫 | 有了 B 才做得出來 |
| D | 課文地圖（分文體四種版型） | 新元件 | 接上 9/30 規格的 `structure_tree` |
| E | 文體專屬活動（分類／解碼／論證配對） | 三個新元件 | 最大，但 A–D 做完才有意義 |
| F | 訊號詞與心情線 | 標記層 | 加分項，可延後 |

**B 是瓶頸也是最花人力的一步**：317 題要逐題標出答案在哪一段、哪一句。
建議先做一冊（四上 12 課、96 題有選項的那批）驗證流程與效益，再決定要不要
全面鋪開。這一步無法全自動——答案句的判定需要讀過課文的人來做。

## 6. 和參考站的三個分歧（刻意不照抄）

| 參考站做法 | 我們的決定 | 理由 |
|---|---|---|
| 提示最後一層用「刪去法」拿掉錯選項 | **不做** | 教的是應試技巧不是閱讀理解；而且支持層只有 2 個選項，刪去法＝給答案 |
| `structure_role` 一段一角色 | 用 9/30 規格的 `structure_tree`（2–5 個結構段，每段涵蓋數個自然段） | 官方結構表本來就是這個形狀；一段一角色是模型錯配 |
| 證據句以明碼存在 lesson 資料裡 | 存**索引**，渲染時從加密課文取 | 明碼存等於把課文片段漏到公開 repo，牴觸 ADR-0034 |

## 7. 驗收標準

- `genre` 全部 55 課都有值且在白名單內。
- 有 `evidence` 的題目，第 3 層提示一定畫得出螢光筆，且畫的句子確實在該段。
- 證據句**不以明碼出現在 `public/data/` 的任何檔案**（加進 `validate-data.mjs`）。
- 每個文體至少一課可以完整走完：地圖 → 一段一段讀 → 文體活動 → 提問 → 主旨。
- 詩歌課次**不出現結構圖**，而且這不算缺漏。
- 三層提示在支持層與挑戰層的行為差異可被測試驗證。
