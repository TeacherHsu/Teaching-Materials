# 課文地圖重新設計規格（草案，待 CF 核可）

日期：2026-09-30｜提案：家中 Mac／Claude｜狀態：**待審，尚未動工**

本規格只描述要改什麼與為什麼，不含實作。CF 核可後才動程式與資料。

## 0. 總原則（CF 2026-09-30 裁定）

**教材設計要能引導、增進學生的閱讀理解，不必拘泥形式。**

「課文地圖」不是一個固定題型，而是一個以理解為目標的模組。結構只是達成理解的
鷹架之一。任何課次，只要既有形式無助於理解，就換一種做法，或者不出題——
不得為了讓每一課都有題目而硬套結構選擇題。

本規格以下所有決定都服從這一條。

## 1. 問題

`paragraph_summary[]` 一段一個 `structure_role`，但官方「課文結構表」給的是
**2–5 個結構段，每段涵蓋數個自然段**。六上 12 課沒有一課是 6 個結構段。

既有生成器只能把 N 個角色塞進前 N 段，其餘填「第4段重點」這類無意義標籤。
55 課共 254 筆待核實角色，根因就是這個模型錯配——維持一段一角色的話，
不論補多少角色詞都會再錯一次。

另一個根因：`extractors/structure_map.py` 讀的是結構表的 **PDF**
（`read_pdf_text`）。結構表實際是直書、由文字方塊拼成的版面圖，PDF 抽文字
會失去二維座標，行序錯亂，因此角色與段落的對應本來就不可靠。

## 2. 設計原則

分成兩層，因為這是兩種不同的知識：

| 層 | 欄位 | 內容 | 用途 | 可否作答 |
|---|---|---|---|---|
| 一 | `structure_type` | 文體基模（封閉集合） | 學生要學會辨認、可遷移到新文章 | ✅ |
| 二 | `section_label` | 官方結構表原文標籤 | 揭曉答案時呈現、當提示 | ❌ 只顯示 |

文體基模（開端／發展／高潮／結尾、提出論點／論據支持／綜合結論）換一篇文章
還能用，是文章結構教學的目標；內容標籤（「觀察自己」「母親料理羹湯的情形」）
只屬於這一篇。把兩者混在同一欄，就是現在白名單顧此失彼的原因。

白名單機制**只留給第一層**：小、封閉、跨冊共用、可回歸測試。
第二層忠實照抄官方結構表，不進白名單，改以「來源可追溯」驗證。

## 3. 資料模型：官方結構表本質上是「樹」

五冊全部抽取比對後可以確定：**每一冊的課文結構表都是階層圖（樹）**，
差別只在深度與是否標段落編號。用單一的樹狀模型可以一次涵蓋所有型態：

```json
"structure_tree": {
  "source": "13課文結構表/PDF/6上L12課文結構表-存根.pdf",
  "nodes": [
    { "label": "一、背景", "paragraphs": [[1]], "children": [] },
    { "label": "二、開端", "paragraphs": [[2,3],[4]], "children": [] },
    { "label": "二、論據支持", "children": [
        { "label": "【論據一】", "paragraphs": [[3],[4]] },
        { "label": "【論據二】", "paragraphs": [[5],[6,7]] } ] }
  ]
}
```

- `label`：官方原文標籤，逐字照抄，匯入時驗證確實出現在該課結構表中。
- `paragraphs`：段落群組陣列，`[[2,3],[4]]` 表示「第 2–3 段」與「第 4 段」兩組；
  官方未標編號時為空陣列。
- `children`：子節點，支援任意深度（四上康軒是三層）。
- `gist_id`：指向改寫後的段落大意，**不放官方原文**。

### 3.1 版權界線（沿用 `extractors/structure_map.py` 既有規則）

- **結構標籤可原文照登**：「總說／分說／起因／經過／結果／開端／高潮」等是
  結構性詞彙。課次專屬標籤（「觀察自己」「母親料理羹湯的情形」）雖非通用詞，
  仍屬結構層次而非課文內容，照登但需標註來源。
- **段落大意一律改寫後才公開**：官方結構表的內容敘述是出版社文字，不得原文
  進 repo。走既有 `rewrite-queue/` → 教師核准 → `apply_rewrites.py` 流程。
- 因此本次匯入**先只寫入樹狀結構（標籤＋段落分組）**，`gist` 留空並產生改寫
  佇列；教師核准前，需要大意文字的活動維持不呈現。
- 子篇（六上 L05 觀樹／種樹）就是兩個並列的頂層節點，各自的段號從 1 起算。
- 並列支（六上 L01 詩／賞析）同理。

`paragraph_summary[].structure_role` 標為 deprecated，保留一版供回溯。

## 4. 各冊實測型態（2026-09-30 全數抽取比對）

| 冊別 | 深度 | 段落編號 | 型態 |
|---|---|---|---|
| 一上 115AG1H | 1（只有葉） | 無 | **完全沒有結構角色**，整份只有 3–5 句課文原句 |
| 二上 115AG2H | 2 | 部分有 | 起因／經過／結果；或總說／分說；角色與內容常**同格**以「—」分隔 |
| 三上 115AG3H | 2 | 有 | 總說／分說（L01 分說=1–4、總說=5）或敘事結構 |
| 四上 115AG4K | **3** | **無** | 康軒：一、大項 →（一）子項 → 1. 細節條列 |
| 六上 115AG6H | 2–3 | 9/12 課有 | 最多樣：子篇、子層、並列支、段落範圍（最多到第 25 段）|

重點結論：

- **一上不適用本模組。** 官方沒有結構角色，現有資料整批是生成的
  （見 §8.4）。一上是注音期韻文，該年段適合的是句子排序或朗讀理解，
  不是結構分析。
- **四上康軒沒有段落編號**，但內容層次豐富，適合做內容歸納而非段落歸位。
- **段落編號不是必要條件**。依 §0，沒有段號就改用不需要段號的理解活動。

## 5. 抽取方式：PDF 轉圖判讀 ＋ WORD 取文字

**Word 不是可靠的管線元件。** 實測 .doc→.docx 的 AppleScript 轉檔反覆卡死
（見 §8），而五冊的結構表資料夾**都同時附有 PDF**，四上康軒另附 JPG。
因此抽取分兩路：

- **文字**：WORD 版可轉檔時走 docx 文字方塊（精確、可逐字比對）；
  轉不動時用 PDF 文字層。
- **階層與段落分組**：**一律由 PDF／JPG 轉圖後判讀**。分組是用大括號畫出來的，
  括號是繪圖物件，任何文字抽取都拿不到，這是本規格最重要的技術結論。

新增 `extractors/structure_table_docx.py`（文字部分）：

1. `.doc` → `.docx`（Word AppleScript，見 §8 的兩個修正）。
2. 讀 `word/document.xml`，取 `v:shape` 內 `w:txbxContent` 的文字，
   同時取 `style` 的 `margin-top` / `margin-left`。
3. 直書還原順序：`left` 由大到小為主序（右→左），同欄 `top` 由小到大。
4. 角色方塊（`一、` `二、` `﹙一﹚`…）與內容方塊依座標歸屬配對。

沿用既有 `common.SourceNotFoundError` 的大聲失敗慣例：抽不到角色或內容時
明確報錯，不得靜默回傳空資料。

## 7. 活動設計：以「讀懂這一課」為目標

**原則（CF 2026-09-30 裁定）：不為了出題而出題。** 模組的目的是引導學生正確
理解課文文意；結構只是達成理解的鷹架之一，不是要考的知識點本身。
因此任務型態由**課文性質決定**，同一個模組允許不同課次呈現不同任務。

### 7.1 任務型態

**A. 段落歸位**（官方有段落編號者）
給該課 3–5 個結構段，把段落大意拖到對應位置。學生必須讀懂每段在講什麼才
放得進去，所以這個操作本身就是理解檢核，而非標籤記憶。
適用：記敘文、論說文、說明文。六上如 L04、L06、L07、L11、L12。

**B. 內容歸納／大意理解**（官方未標段落編號者，如四上康軒全冊、六上詩與文言）
呈現完整結構骨架（`section_label` ＋ `gist`）供閱讀，不出結構題。
理解檢核改用官方結構表已提供的**主旨**與**賞析**內容設計，聚焦
「這一課在說什麼」。
適用：六上 L01〈遇見自己〉、L03〈孔子說的話〉、L10〈過故人莊〉。

不得為了讓 B 類課次「也有題目」而把內容標籤（如「觀察自己」）當成結構答案
硬出選擇題——那既不忠於官方教材，也不構成理解。

### 7.2 共同鷹架

1. **先讀骨架**：兩類任務都先呈現已填好的結構圖，建立「文章有形狀」的概念。
2. **再做任務**：A 類進段落歸位，B 類進大意理解。
3. **答錯先提示，第二次才揭曉**（沿用既有設計底線）。

3–5 個結構段本身即良好 chunking，優於 6 個平行的「第N段重點」。
照官方分段同時更忠實也更好教。

其餘沿用既有設計底線：朗讀按鈕只放喇叭圖示、正文 ≥22px、
一個畫面一個任務、375px 不得橫向捲動、尊重 prefers-reduced-motion。

## 8. 順帶要修的既有缺陷

**8.1 `convert_doc.py` 會存錯檔案。** 目前流程是
`open` → `set theDoc to active document` → `save as`。當 Word 殘留前次未關閉的
文件時，`active document` 取到的是**舊文件**，會把舊內容存成新檔名。
本次實測已重現：L01 被存成 L07 的內容。
修正：`save as` 前先 `close every document saving no`。

**8.2 Word 對話框造成 60 秒逾時。** 加 `set display alerts to none` 後解決。
未加時每一課都逾時失敗。

**8.4 一上教材地圖整批無來源。** 官方 08課文結構表 L01–L07 只有課文原句，
沒有結構角色也沒有段落大意；但 repo 的 115AG1H 七課共 26 筆 `paragraph_summary`
都有生成的 `structure_role`（開端／發展／轉折／收束）與 `summary`（起／承／合），
且 `status` 全為 `approved`。已於 2026-09-30 加冊別層級 fail-closed 擋下
（`UNSOURCED_VOLUMES`），資料未刪，待重新確認該年段活動後處理。

**8.3（環境）OneDrive 路徑無法轉檔。** `~/mandarin-work` 現為 OneDrive
symlink，Word 對 `~/Library/CloudStorage/` 下的檔案走保護檢視，AppleScript
`save as` 無聲卡死。暫行作法是先複製到純本機路徑再轉；`convert_doc.py`
應正式加入「暫存到本機再轉」的步驟，否則後續任何人直接跑匯入器都會撞到。
